# 操作手册

## 启动与登录

按 stage2/README 初始化后，在仓库根运行 `python -m stage2`（须使用已安装依赖的.venv解释器），或双击“启动第二阶段.bat”。打开 http://127.0.0.1:5000。先在本地private目录查当前数据库的账号密码，不要把密码贴入报告、截图或公共GitHub。登录失败只显示“用户名或密码错误”，不会显示账号哈希和数据库信息。

## 顾客与散客

1. 用 customer 或 guest 登录，查看饮品菜单与库存。会员顾客对应M001；guest为无会员散客。
2. 打开“订单中心”，选择饮品与杯数；可“添加明细”购买多种饮品，也可同种饮品分两行；“移除”删除不需要的行。至少保留一行。
3. “保存草稿”后查看订单编号、状态、成交单价与总额。此时不扣库存。编辑会用当前菜单重新报价；保存后的成交价不随之后菜单改价自动改变。
4. 点“编辑”调整明细与杯数，保存后即时反馈；点“删除”只删除自己的草稿及明细。草稿也可取消并保留记录。
5. 等待店员核对并确认；再次进入订单中心查看已完成状态。顾客看不到其他人的订单、商品维护、库存盘点或销售统计入口，也不能通过自行调用API绕过。

## 店员

1. 用 clerk 登录，订单中心展示所有订单。
2. 核对草稿明细后点击“确认”。一次操作同时检查商品、库存，扣减库存并完成订单，填写操作员工；不会对历史开库订单重复扣库。
3. 库存不足或已取消/已完成的订单再次确认时，界面给出友好提示，整笔操作回滚。
4. 查看“库存查询”确认可售杯数变化；查看“销售统计”核对完成单销量和金额。
5. 新系统完成单可以“取消订单”，库存只回补一次；历史v0.1订单在盘点之前，不能按新流水直接取消回补。完成单不得删除/改明细。

## 管理员

1. 用 admin 登录，在菜单页表单输入编号、名称、类别、价格、阈值与上架状态，点击“保存商品”；同时登记零库存。
2. 商品卡片点“编辑”，修改价格或上下架。修改当前菜单价不改变已保存订单明细中的历史价格。
3. 库存页在盘点表单输入商品编号与实际可售杯数，“保存库存”可新登记或更新。只有数量为零的库存记录可删除；删除后菜单保留，并显示“未登记”。
4. 删除无订单引用且库存为零的商品；有历史订单引用时数据库会拒绝删除，可改为下架。错误后库存删除也回滚，不会破坏引用关系。
5. 管理员可以执行店员订单操作，但没有DDL、数据库所有者或账号管理权限。

## 错误反馈与排查

| 提示或错误码 | 操作建议 |
| --- | --- |
| INPUT_INVALID | 检查必填、杯数整数、价格最多两位小数、编号格式与明细行数 |
| UNAUTHENTICATED / AUTH_FAILED | 重新登录；核对本机生成的账号密码 |
| FORBIDDEN | 使用有对应职责的账号；顾客仅维护自己的草稿 |
| NOT_FOUND | 刷新后重新选择，或确认订单归属 |
| BUSINESS_RULE | 检查商品是否上架、库存是否充足、订单状态是否允许操作 |
| CONSTRAINT_CONFLICT | 检查编号重复、会员编号存在性和被历史订单引用情况 |
| DB_UNAVAILABLE | 稍后重试；维护人检查SQL服务与配置；用户界面不显示内部连接错误 |
| TRANSACTION_FAILED | 数据已回滚；保存界面请求编号，交维护人查看后端JSONL日志 |
| CSRF_INVALID | 刷新页面后重新提交 |

开发人员按界面编号在 logs/app.jsonl 查找 request_id，结合时间、操作、角色与detail定位；不要把详细日志直接展示给顾客。SQL Server服务仍使用原有Windows身份验证模式，不需重启或更改认证设置。
