# 阶段一实验报告：数据库初建与 CRUD

## 目标与设计思路

本阶段按课程第 1–4 周任务把校园奶茶店需求转成 SQL Server 关系库，主体实现包括建库、装载、增删改查、多表查询、统计视图、数据库约束和不同角色授权。采用六张核心表。订单明细记录当时成交单价，避免菜单改价后覆盖历史交易；会员外键允许空值以保留匿名购买；库存仅是标准饮品可售杯数快照，不声称已实现配方、原料核算或下单扣减事务。课程验收尚未全部完成：第二周的真实业务样例数据缺失，当前最终脚本组合尚未从空库完整复跑，组内分工待本人填写。

## 实验环境

Microsoft SQL Server 2025 Express，实例 `SQLEXPRESS`，Windows 集成认证，本机 SQLCMD 18 / ODBC Driver 18。用 `-C` 接受本机实例证书。具体服务器版本保存在 `result/server-version.txt`。之后安装 SSMS 22.10.12217.157 并成功连接同一实例；`03`–`08` 脚本已在 SSMS 中重跑并成功执行，真实结果截图保存在 `result/screenshots/`。未测试 SQL Server 2022 或其他环境。

## 复现过程与观察

1. 从 `master` 创建新数据库 `MilkTeaShopV01`。
2. 在第一次复现中按序执行建库、六表 schema、样例装载和 CRUD/查询/视图/约束/权限脚本；公开菜单参考数据加入后，在既有课程样例基线上另行运行带保护条件的 `09_update_public_menu.sql`，然后复跑 `03`–`08`。
3. CRUD 脚本在事务内分别对 Product、Inventory、ShopOrder 和 OrderLine 演示新增、读取、修改、删除；订单明细修改杯数后重新计算金额。脚本最后回滚，因此执行前后基线相同，可重复运行。
4. 样例查询按订单状态限制完成订单，订单明细粒度为一行一商品行。零销量商品通过 `LEFT JOIN` 保留，避免误把未销售商品过滤掉。
5. CHECK、UNIQUE、FK 拒绝负库存、重复订单号/手机号、孤儿订单明细和非法数量；有效对照行能够成功插入后回滚。
6. 店员演示用户能读商品/库存视图并新增订单头与订单明细；改商品价格、删商品与直接读员工表失败。店长角色只获得六张业务表的维护权和视图读取权。演示用户没有登录凭证。

实际输出见 `../result/`。运行数量和错误号以输出文件为准，不能把预期错误文本代替数据库观察。

## 阶段总结

主体原型脚本已在本机 SQL Server 2025 验证，包含需求与边界、字段/键说明、六表建库装载、CRUD、多表和统计查询、三个视图、完整性反例、角色最小授权、AI记录和分工模板。历史证据显示 `00`–`08` 曾从空库运行；此后加入 `09` 并调整部分脚本，当前最终 `00`–`09` 尚未再次从空库整体复跑。因此本报告记录的是主体实现和分阶段验证，不将其称为课程 v0.1 最终验收完成。设计保留交易时价格与匿名购买，同时不把未经设计的库存联动、支付、采购补货写成已实现能力。
