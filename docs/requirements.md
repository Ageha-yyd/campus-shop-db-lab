# 需求、角色与数据边界

## 场景

校园小卖部在营业时出售饮料和零食。店员为顾客录入一张订单及多条商品明细；订单保存成交时商品单价，避免日后商品调价改写历史成交金额。顾客可以匿名购买；自愿提供会员号时，订单可以关联会员。店长维护商品和员工信息并查看汇总。当前只记录确认完成或取消的订单。

## 主要流程

1. 店员选择已启用商品并录入数量；需要记录会员时选择可选会员，否则保持匿名。
2. 数据库按商品、数量和成交单价保存订单明细；订单明细引用订单和商品。
3. 店员/店长查看订单与商品汇总；店长维护商品、库存快照和员工资料。
4. 取消订单用状态表示；本版本不自动返还库存，也不模拟支付/退款。真实实施前需要明确库存流水与状态变更规则。

## 角色与职责

| 角色 | 当前职责 | 数据库权限目标 |
| --- | --- | --- |
| 店长 | 维护商品、库存、员工；读取全部订单与报表 | 读取/维护业务表与视图 |
| 店员 | 创建订单、明细；读取商品、库存和订单报表 | 读取商品/库存/报表；新增订单及明细；不能改商品定价或库存 |
| 会员/匿名顾客 | 提供可选会员号并购买；不直接连接数据库 | 无数据库账户；由店员代为录入 |

角色是业务身份，数据库角色是权限集合。脚本创建无登录名的演示用户用于本机 `EXECUTE AS USER` 验证，不创建 Windows 登录、密码或生产账户。

## 数据边界

| 信息 | 纳入 | 理由/限制 |
| --- | --- | --- |
| 商品编码、名称、分类、当前标价、启用状态 | 是 | 支持商品识别、定价与查询 |
| 商品当前库存数量与更新时间 | 是 | 本版仅作为库存快照；没有完整出入库流水 |
| 订单号、时间、员工、可选会员、状态 | 是 | 支持交易追踪；匿名订单允许会员外键为空 |
| 订单明细中的商品、数量、成交单价 | 是 | 保存交易时事实及历史金额 |
| 员工编号、姓名、岗位 | 是 | 记录经办人；当前为虚构样例 |
| 顾客姓名、住址、支付卡号、口令 | 否 | 与当前查询目标无关，避免不必要敏感信息 |
| 供应商、采购单、补货、支付/退款流水 | 否 | 未定义业务规则，留待后续需求确认 |
| 会员真实姓名、生日、完整联系方式 | 否 | 当前无需收集；会员使用虚构/匿名化演示标识 |

## 未决问题

- 商品是否允许同一订单拆成重复明细行？当前主键允许，汇总按商品累计。
- 取消订单何时释放库存、如何记录审计？未实现。
- 库存快照如何与销售和盘点流水保持一致？当前没有库存流水表，故不宣称闭环库存核算。
- 售价变更是否需要生效时间/操作者审计？本版仅保留当前价与历史成交价。
