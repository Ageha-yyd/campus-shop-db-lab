学习者在 2026-10-05 确认使用更简单的奶茶店场景。本轮相应更新数据库名、样例和记录，并在新的 `MilkTeaShopV01` 上从空库完整复现过 00–08 八个阶段脚本；SQLCMD `-b` 均返回成功，最终断言为 `PASS`。当前版本另有脚本 09 用于安全更新已存在的阶段一样例菜单。菜单参考数据取自 `docs/data-sources.md` 所列公开网页；交易、库存与身份数据仍为虚构样例。标准执行使用 SQLCMD `-f 65001` 读取 UTF-8，并在涉及过滤唯一索引的脚本中显式设定 SQL Server 所需 ANSI 选项。

为逐项覆盖第三周 CRUD 要求和第四周明细权限要求，后续改进了 `03_crud.sql` 与 `07_roles.sql`，并在现有 `MilkTeaShopV01` 上重新执行这两个脚本和 `08_acceptance.sql`；三次 SQLCMD `-b` 均返回 0，验收仍为 `PASS`。CRUD 新增商品价/名修改、订单状态修改与恢复、明细杯数修改（金额从 5.00 变为 7.50）及各类删除行数；店员可新增订单头和订单明细，各返回 1 行，商品修改、读取员工表和删除商品仍被拒绝。对应输出见 `result/03_crud.txt`、`result/07_roles.txt`、`result/08_acceptance.txt`。这一轮没有删除或重建现存数据库。

响应学习者允许采用公开菜单数据的建议，加入 `09_update_public_menu.sql`：只接受固定三商品、三订单和四条明细的课程样例基线，更新产品目录价及对应虚构订单的成交价快照。脚本在现有库运行成功；随后重跑 `03`–`08` 更新 CRUD、查询、视图、约束、角色和验收输出。当前销售统计为 D001 珍珠奶茶 3 杯/18.00、D002 满杯百香果 1 杯/7.00、D003 冰鲜柠檬水 0 杯完成销售，验收输出为 `PASS`。这不是从空库再次运行 00–09 的证据；从空库复现步骤已在 README 加入 09。

迭代时发现并修正了以下问题；最终 `result/` 只保留最终复现输出及一份建表失败记录：

1. `LineNo` 在目标 T-SQL 解析中触发语法错误，改为 `LineNumber`。
2. SQLCMD 的默认 `QUOTED_IDENTIFIER` 设置不满足过滤唯一索引建表和写入要求；在 schema、seed、CRUD、约束脚本中显式设置 ANSI 选项，并以 `-f 65001` 运行。
3. 最初的负库存测试用已有商品键，数据库先以重复主键拒绝；改用合法对照事务内新增的临时商品，最终观察到 `CK_Inventory_Quantity_Nonnegative` 拒绝。

这些修正都针对运行证据完成。最终完整复现包括修正后的六类验证（CHECK、主键/候选唯一、FK、CRUD 回滚、权限允许/拒绝）与基线断言。
